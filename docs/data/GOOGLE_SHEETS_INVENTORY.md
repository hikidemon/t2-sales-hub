# T2 Sales Hub — Инвентаризация источников данных

Документ описывает структуру проанализированных таблиц, выявленные связи между ними
и данные, необходимые личному кабинету продавца.

**Дата анализа:** 21.10.2026
**Источники:** 7 файлов `.xlsx`, приложенных к задаче (выгрузки из Google Sheets)
**Метод:** разбор через `openpyxl` (структура, формулы, кэшированные значения) + проверка
доступности Google-таблиц по HTTP (gviz/export) и по их ID, извлечённым из формул.

> **Важно.** Все приложенные файлы содержат **реальные персональные данные сотрудников**
> (ФИО, должности, торговые точки, часы работы). Оригиналы не изменялись и не копировались
> в репозиторий. Правила обезличивания — в разделе [«Правила обезличивания»](#правила-обезличивания).

### 2.3. Проверенные способы чтения

```bash

# Конкретная вкладка по gid + Google Query Language
```

актуальными данными за 20.10.2026. Таблица `19br1bP3…` возвращает **HTTP 410** — чтение
невозможно, требуется её восстановление или альтернативный источник.

Блоки показателей:

> находятся в листе «ЗП» торговой точки. См. `MOTIVATION_RULES.md`.

### 3.2. «ЗП» — расчёт зарплаты по точке

Файл `г. Новосибирск, пр. Карла Маркса, д.7.xlsx`, лист `ЗП`, 24 строки × 37 столбцов.

- **Строки 1–11** — сводка по показателям: `План` (стр. 5), `План на день` (6),
  `План на сотрудника` (7), `Факт` (8), `Не хватает до плана` (9), `Прогноз плана` (10),
  `Процент выполнения` (11).
- **Строки 14–22** — расчёт по каждому сотруднику: столбцы `Д-сть | Грейд | ФИО | Оборудование |
Аксессуары | ПДУ | Плоттер | Trade-In | Страхование | Яндекс/Касперский | Кредитование |
Карты | ДИ+РТК ШПД | АО РТК | Подписки всего | UpSale | СИМЫ | MNP | VMR | Премия |
ОКЛАД | % | ЗП`.
- **Столбцы AK–AM** — блоки премий ССП: «Админ. блок», «Блок Top UP», «GI», «Комбо», «MNP»,
  «АО РТК + ВН + ДИ», «Аксессуары+ПДУ».

Ключевые формулы (приведены в исходнике, воспроизводятся точно):

```
План на день        = ROUNDUP(План / (Дней в месяце − Отработано дней), 0)
План на сотрудника  = План на день / 2
Факт                = SUM('Лист_продаж'!C545:AG545)   (по каждому показателю своя строка)
Не хватает до плана = План − Факт
Прогноз плана       = (Факт / Отработано дней × Дней в месяце) / План
Процент выполнения  = Факт / План
```

### 3.3. «Лист_продаж» — матрица продаж

622 строки × 111 столбцов. Строка 2 — даты (ссылаются на лист «график»). Строки 543–618 —

Комбо, MNP, UpSale). Столбцы C+ — дни месяца. Верхняя часть (стр. 4+) — **разбивка по сотрудникам**,

### 3.4. «график» — расписание и часы

15 строк × 53 столбца. Столбцы: `Д-сть | Фамилия СП | Часы | <дни>`.
Строки 4–11 — сотрудники с должностями (`ССП`, `Подмена`, `СП`, `СТ`) и фамилиями;
столбец C — `SUM(D:AH)` (часы за месяц). Фамилии подтягиваются из «Общие».

### 3.5. «ПРАВИЛА ВЕДЕНИЯ» — регламент работы с таблицей

6 пунктов, критичных для понимания данных:

1. Редактируются только ячейки с белым фоном, остальные защищены.
2. Фамилии в «Листе продаж» подтягиваются автоматически из «графика».
3. **Два кредита в один день — вносить в две соседние ячейки**, иначе бонус за кредитование
   посчитается как за одну продажу.
4. В начале месяца переносятся заявки прошлого месяца в «Контроль МНП» и «Контроль Аладдин+РТК».
5. Реализации комбо указываются в штуках в одной строке, дублировать по ТП не нужно.
6. **Раздел «ЗП» рассчитывает исключительно примерную сумму выплат** — по общей мотивации
   региона, без доп. выплат по договорённостям и временным мотивациям.

### 3.6. «График НР 2026.xlsx» — расписание СП

20 скрытых листов: месяцы 2026 × берег (Правый/Левый). Строки — торговые точки с часами работы ТТ,
столбцы — даты (пара «дата + время работы СП»), значения — фамилия сотрудника и его смена.
**Формул нет** — это справочные данные.

### 3.7. «Копия Планы продаж НР.xlsx» — индивидуальные планы

215 листов, по одному на сотрудника (`Елезова Ксения`, `Золотов Даниил`, …), все скрытые.
Структура каждого: строки 4–12 — показатели (Оборудование, Аксессуары, ПДУ, Плоттер,
Страхование, Combo, ESET, РТК/ДИ заявки) с планом в столбце B, фактом в C
(`SUM(H:AA)`), остатком в D и `% выполнения` в E. Столбцы H+ — дни месяца.
Заголовок: «Индивидуальные планы СТ (22 рабочих дня)», «Общий план на 20 дней».

### 3.8. «Комбо НСК .xlsx» — остатки комбо-товаров

4 листа: `Combo 35%`, `Combo 30%`, `infinix 30%`, `Cток смартфонов`.
Строки — номенклатура ( Tecno Camon 50, Realme C100i, Infinix Note 60 и др.), столбцы — салоны
с указанием количества. Строки «Итог» — суммы. Формул нет.

### 3.9. «Единый Калькулятор Combo .xlsx» — расчёт скидок

7 листов. `Исходные данные` (506 строк) — бренд/модель/скидка/доп. продукты;
`Dash` — калькулятор; `КАЛЬКУЛЯТОР КОМБО V2.1` и `КАЛЬКУЛЯТОР КОМБО Единый` — сценарии
скидок 15/20/30/40/50 %; `Список моделей в Combo` — перечень моделей, участвующих в акции.

Ключевая формула (лист `Dash`):

```
Стоимость со скидкой = Стоимость смартфона × (100% − базовая скидка − доп. скидка)
Общая сумма по акции = Стоимость − (Стоимость × (скидка% + доп. скидка%)) + Страхование + Доп. продукт
Выгода для клиента   = Общая сумма без акции − Общая сумма по акции
```

## 4. Связи между источниками

```
                 ┌──────────────────────────────────────────────┐
                 │  «Общие» 1GNAUy6…  (живая, публичная)         │
                 │  ├ Отчет (515868842)      План/Факт/%/Прогноз│
                 │  ├ Планы (1101403177)     планы по ТТ        │
                 │  ├ Выполнение планов (0)  план/факт по дням  │
                 │  └ Дневной план (1431075653)                  │
                 └───────────┬───────────────────┬──────────────┘
                             │ B1 → ссылка        │ импорт «Общие» A1:AF500
                             ▼                   ▼
┌────────────────────────────┐   ┌──────────────────────────────────┐
│ «для расчетов 10.2026»     │   │ Торговая точка (файл .xlsx)      │
│ 17Nnk… (живая, публичная)  │   │  график → Лист_продаж → ЗП       │
│  вкладки по регионам       │   └──────────────────────────────────┘
│  Новосибирск (1660743445)  │                    │
└────────────────────────────┘                    │ применяет
                             │                    ▼
                             │   ┌──────────────────────────────────┐
                             │   │ «Мотивация Т2 15.10.2026»       │
                             │   │  тарифные сетки и правила        │
                             │   └──────────────────────────────────┘
                             │
                             ▼
                  ┌──────────────────────┐
                  │ График НР 2026       │  (расписание → часы → ОКЛАД)
                  │ 20 листов, справчно  │
                  └──────────────────────┘
```

**Направление зависимостей (подтверждено формулами):**

- Торговая точка (`ЗП`!`B1`) → ссылается на «для расчетов» (`17Nnk…`) для планов по точкам.
- Торговая точка (`ЗП`!`W1`) → ссылается на «Общие» (`1GNAUy6…`) для справочника точек и календаря.
- Торговая точка (`Лист_продаж`) → ссылается на свой же «график» (даты, фамилии).
- Торговая точка (`ЗП`) → применяет тарифы из «Мотивации Т2».
- «Мотивация T2» — **не ссылается ни на что** (чистый регламент, 0 формул).
- График НР 2026 — **не связан формулами** с остальными (справочный).
- «Единый Калькулятор Combo» → ссылается на справочник `19br1bP3…` (**недоступен, HTTP 410**).

## 6. Персональные и конфиденциальные данные

Обнаружено в приложенных файлах:

- **Должности/статусы** — ССП, СТ, СП, Подмена, Стажер, Наставник.
- **Торговые точки и адреса** — до 20 точек НСО с полными адресами.
- **График рабочего времени** — почасовые смены конкретных сотрудников по дням.
- **Индивидуальные планы продаж** — по каждому сотруднику (215 листов).
- **Расчётные суммы мотивации** — фактические ЗП и бонусы (персональные данные).

### Правила обезличивания

1. Оригинальные файлы **не изменяются** и **не попадают в репозиторий**.
2. Для демонстрации используются **отдельные копии** с заменой ФИО на стабильные псевдонимы
   `EMP-001`, `EMP-002`, … Соответствие ФИО ↔ псевдоним хранится **только в защищённом процессе
   подготовки данных** и не публикуется.
3. Сохраняются структура таблиц, логика формул, взаимосвязи и ссылочная целостность.
4. В UI демо-режим маркируется явно; синтетические суммы не выдаются за реальные выплаты.
5. Официальные формулы мотивации **не переписываются** — извлекаются как есть и помечаются
   источником.

## 8. Метод чтения: рекомендация

Три варианта доступа, в порядке предпочтения:

1. **Google Sheets API** (OAuth/сервисный аккаунт) — даёт и значения, и вычисленные формулы,
   поддерживает инкрементальные изменения. Требует выдачи прав владельцем.
2. **Публичный gviz/export** — проверено, работает для `1GNAUy6…` и `17Nnk…` **прямо сейчас**,
   без авторизации. Ограничения: отдаёт **вычисленные значения** (а не формулы), имена листов
   надо передавать по `gid`, нет гарантии кэширования.
3. **CSV-экспорт** — рабочий вариант для проверки архитектуры, пока нет авторизации.

Для серверной части проекта `packages/core` уже подготовлен контракт
`DashboardDataSourceAdapter` (`fetchDashboard(periodId)`), а `MockDashboardAdapter` реализует
его для автономной разработки. Следующий слой — `GoogleSheetsAdapter` с тем же интерфейсом.
