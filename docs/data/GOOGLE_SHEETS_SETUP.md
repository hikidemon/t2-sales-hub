# T2 Sales Hub — Настройка доступа к Google Sheets

Инструкция по подключению Google Sheets как источника данных для сервера.

> **Важно:** не делайте рабочие таблицы публичными ради простоты интеграции.
> Документ должен содержать только те данные, которые допустимо показывать.
> Персональные данные сотрудников — обезличивайте (см. раздел 6).

---

## 1. Три способа доступа

| Способ                                      | Что нужно                    | Когда применять                                      |
| ------------------------------------------- | ---------------------------- | ---------------------------------------------------- |
| **A. Публичная ссылка (gviz/export)**       | Таблица доступна «по ссылке» | Демонстрация, проверка архитектуры. **Уже работает** |
| **B. Google Sheets API, сервисный аккаунт** | JSON-ключ + права на таблицу | Продакшн, приватные таблицы                          |
| **C. Google Sheets API, OAuth**             | OAuth-клиент, consent screen | Когда доступ должен быть у конкретного человека      |

Способ **A** реализован в текущем коде (`GoogleSheetsAdapter`).
Способы **B** и **C** требуют замены транспорта — контракт `DashboardDataSourceAdapter`
при этом не меняется, см. раздел 5.

---

## 2. Способ A: доступ по ссылке (текущая реализация)

### 2.1. Что нужно от владельца таблицы

1. Открыть таблицу → «Доступ» → «Общие ссылки» → «Любой, у кого есть ссылка» → «Читатель».
2. Прислать ID документа (часть между `/d/` и `/edit` в URL) и gid нужной вкладки.

ID и gid уже извлечены из предоставленных файлов — см. `GOOGLE_SHEETS_INVENTORY.md`:

| Документ               | ID                                             | Вкладка     | gid          |
| ---------------------- | ---------------------------------------------- | ----------- | ------------ |
| «Общие» (сводка НСО)   | `1GNAUy6QoKHUm9DLa3PmhsDoX6iaYr6r5otrjTl8AYiw` | Отчёт       | `515868842`  |
| «для расчетов 10.2026» | `17Nnk5A9YBLQLRXhTfLoTBlFEiDP94fDb2wIOXrQHrGg` | Новосибирск | `1660743445` |

### 2.2. Настройка

Скопируйте `.env.example` в `.env` и заполните:

```bash
DATA_SOURCE=google-sheets
GOOGLE_SHEETS_SPREADSHEET_ID=1GNAUy6QoKHUm9DLa3PmhsDoX6iaYr6r5otrjTl8AYiw
GOOGLE_SHEETS_REPORT_GID=515868842
```

`.env` не попадает в Git (проверено: `.gitignore` содержит `.env`).

### 2.3. Проверка

```bash
pnpm --filter @t2-sales-hub/api dev

curl http://localhost:3001/api/sync/status
# {"state":"ok","source":"google-sheets","lastSuccessAt":"...","lastDurationMs":749,...}

curl http://localhost:3001/api/dashboard | head -c 400
```

## 3. Способ B: сервисный аккаунт (рекомендуется для продакшна)

### 3.1. Что должен сделать владелец (вручную, вне чата)

1. **Google Cloud Console** → создать проект (или взять существующий).
2. **APIs & Services** → **Library** → включить **Google Sheets API**.
3. **APIs & Services** → **Service Accounts** → **Create service account**
   (имя, например `t2-sales-hub-sync`).
4. Создать **JSON-ключ** (тип `JSON`) и **сохранить файл** в безопасном месте.
   Приватный ключ **не пересылайте в чат** — он попадёт в историю переписки.
5. Открыть нужную таблицу → «Доступ» → «Добавить пользователя или группу» →
   вставить **email сервисного аккаунта** (`...@...iam.gserviceaccount.com`) →
   роль **«Читатель»**.
6. Для второй таблицы (если она тоже нужна) — повторить шаг 5.
7. Передать сервисному аккаунту доступ к **конкретным вкладкам**, если это важно:
   «Общий доступ» → «Всегда использовать эти значения» в выпадающем списке «Конкретные люди».

### 3.2. Что разместить на сервере

Файл ключа (`t2-sales-hub-sync.json`) — вне репозитория, в защищённом хранилище
(переменная окружения с путём к файлу, Kubernetes Secret, HashiCorp Vault, Yandex Lockbox).

```bash
GOOGLE_APPLICATION_CREDENTIALS=/run/secrets/t2-sales-hub-sync.json
```

### 3.3. Что нужно изменить в коде

Транспорт в `packages/core/src/adapters/GoogleSheetsAdapter.ts` заменяется на вызов
Sheets API (`spreadsheets.values.get`). Контракт `DashboardDataSourceAdapter`
и весь код выше по стеку остаётся без изменений — меняется только реализация
`readRows()`.

## 4. Переменные окружения

Полный список — в `.env.example` (без секретов).

| Переменная                     | По умолчанию | Назначение                                                     |
| ------------------------------ | ------------ | -------------------------------------------------------------- |
| `DATA_SOURCE`                  | `mock`       | `mock` \| `google-sheets`                                      |
| `GOOGLE_SHEETS_SPREADSHEET_ID` | —            | ID документа                                                   |
| `GOOGLE_SHEETS_REPORT_GID`     | `515868842`  | gid вкладки с отчётом                                          |
| `GOOGLE_SHEETS_TIMEOUT_MS`     | `15000`      | Тайм-аут одного чтения                                         |
| `SYNC_INTERVAL_MS`             | `300000`     | Интервал автосинхронизации (5 мин)                             |
| `SYNC_MAX_RETRIES`             | `3`          | Число попыток при сбое                                         |
| `SYNC_STALE_AFTER_MS`          | `900000`     | После какого возраста снимок считается устаревшим (15 мин)     |
| `SYNC_REFRESH_TOKEN`           | —            | Секрет для `POST /api/sync/refresh`; пусто → endpoint отключён |

**Секреты читаются только из `process.env`.** В клиентскую сборку они не попадают:
`apps/web` обращается только к `/api/*` и не знает ни об ID таблиц, ни о токенах.

Генерация секрета:

```bash
openssl rand -hex 32
```

## 5. Как подключить 1С позже (без переписывания страниц)

Архитектура уже подготовлена:

```
Google Sheets → GoogleSheetsAdapter ─┐
1С             → OneCAdapter         ─┼→ DashboardDataSourceAdapter
                                       │        ↓
                              DataSyncService (кеш, ретраи, статус)
                                       ↓
                              /api/dashboard → React
```

Чтобы добавить 1С:

1. Реализуйте `OneCAdapter` с методом `fetchDashboard(periodId)` в
   `packages/core/src/adapters/` — интерфейс уже определён.
2. Добавьте ветку выбора в `apps/api/src/modules/sync/service.ts`
   (`createDataSourceAdapter`).
3. Добавьте `DATA_SOURCE=onec` и нужные переменные в `env.ts` и `.env.example`.
4. **Страницы, виджеты и форматирование не меняются.**

Если схема 1С отличается, добавьте второй нормализатор
(по образцу `packages/core/src/data/normalizeDashboardRows.ts`) — контракт
`fetchDashboard` возвращает тот же `DashboardData`.

## 6. Правила обезличивания

Приложенные исходные таблицы содержат реальные ФИО, должности, торговые точки,
графики работы и суммы мотивации.

Для демонстрации:

1. Оригиналы не изменяются и не копируются в репозиторий.
2. Используются отдельные копии с псевдонимами `EMP-001`, `EMP-002`, …
   Соответствие ФИО ↔ псевдоним хранится **только** в защищённом процессе
   подготовки данных.
3. Структура таблиц, логика формул и ссылочная целостность сохраняются.
4. Синтетические суммы не выдаются за реальные выплаты; деморежим помечен
   в интерфейсе.
5. Официальные формулы мотивации **не переписываются** — извлекаются как есть
   со ссылкой на источник (см. `MOTIVATION_RULES.md`).

## 7. Ограничения текущей реализации

| Ограничение                                                     | Следствие                                                                     | Как снять                                                         |
| --------------------------------------------------------------- | ----------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| Чтение через gviz отдаёт **вычисленные значения**, а не формулы | Формулы листа недоступны — реализованы только те, что восстановлены из файлов | Перейти на Sheets API (способ B)                                  |
| gviz отдаёт первый лист при неверном `gid`                      | Ошибка в gid не видна сразу — вернётся другой лист                            | Проверять gid; в способе B gid точен                              |
| Изменения видны не мгновенно                                    | Интерфейс может показывать данные предыдущей синхронизации                    | Это ожидаемо; кеш показывает время последнего обновления          |
| Справочник `19br1bP3…` (модели для Combo) недоступен — HTTP 410 | Расчёт скидок Combo не воспроизводится                                        | Восстановить таблицу или предоставить выгрузку                    |
| Таблица «Мотивация Т2» существует только как `.xlsx`            | Правила мотивации зафиксированы в коде, а не читаются из таблицы              | Предоставить таблицу — тогда сетки тарифов можно вынести в данные |
| Нет авторизации пользователей                                   | Каждый видит демо-профиль                                                     | Вне scope текущего этапа                                          |

## 8. Проверка после настройки

```bash
# 1. Синхронизация прошла
curl http://localhost:3001/api/sync/status
# ожидается: "state":"ok","source":"google-sheets"

# 2. Данные отдаются
curl http://localhost:3001/api/dashboard | head -c 300

# 3. Ручное обновление (нужен токен)
curl -X POST -H "x-sync-token: $SYNC_REFRESH_TOKEN" http://localhost:3001/api/sync/refresh

# 4. Frontend показывает источник и время обновления
node scripts/t2-responsive-check.mjs
node scripts/t2-interaction-check.mjs
```

Изменение значения в таблице становится видно после следующей синхронизации
(по умолчанию — до 5 минут) либо сразу после `POST /api/sync/refresh`.
