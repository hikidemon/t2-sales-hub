# T2 SALES HUB — Архитектура

## Workspace

```
t2/
├── apps/
│   ├── web/          React SPA (Vite) — личный кабинет продавца
│   └── api/          Express API — данные, синхронизация, уведомления, тесты
├── packages/
│   ├── core/         Доменная логика, правила, адаптеры, синхронизация (без React)
│   ├── ui/           Design system: токены и переиспользуемые компоненты
│   └── config/       Tailwind-пресет, tsconfig, eslint
├── docs/
│   ├── data/         Инвентарь источников, правила мотивации, настройка доступа
│   └── design/       Дизайн-система T2
├── scripts/          Браузерные проверки (CDP) и извлечение дизайн-токенов
└── .env.example      Шаблон конфигурации сервера (без секретов)
```

## Слои и направление зависимостей

```
app → pages → widgets → features → entities → shared
                                          ↘ packages/core
                        widgets/pages  → packages/ui
```

Зависимости идут **только вниз**. `shared` не импортирует верхние слои;
`entities` — `features`/`widgets`/`pages`/`app`.

`packages/core` не зависит ни от React, ни от UI. `packages/ui` зависит только от
`react`/`clsx`.

## Feature-Sliced Design в `apps/web/src`

| Слой       | Ответственность                          | Содержимое                                                                                                                                                                                                              |
| ---------- | ---------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `app`      | Инициализация, провайдеры, маршрутизация | `index.tsx`, `router/`, `providers/`, `layouts/RootLayout.tsx`, `styles/`                                                                                                                                               |
| `pages`    | Сборка страниц                           | `home/ui/HomePage.tsx`                                                                                                                                                                                                  |
| `widgets`  | Крупные композиционные блоки             | `app-shell`, `dashboard-header`, `income-summary`, `plan-progress`, `kpi-cards`, `dynamics-chart`, `ranking`, `forecast`, `motivation`, `recent-operations`, `sync-status`, `notification-bell`, `quiz`, `integrations` |
| `features` | Пользовательские сценарии                | пусто — сценариев, требующих отдельного слайса, не было                                                                                                                                                                 |
| `entities` | Модели предметной области                | `employee/model/seller.ts`                                                                                                                                                                                              |
| `shared`   | Общая инфраструктура                     | `api/dashboard.ts`, `config/`, `lib/cn.ts`                                                                                                                                                                              |

Каждая папка слайса имеет `index.ts` — публичный API.

### Контракты источников

```ts
interface DataSourceAdapter {
  readonly kind: 'mock' | 'google-sheets' | 'onec';
  isAvailable(): Promise<boolean>;
}

interface DashboardDataSourceAdapter extends DataSourceAdapter {
  fetchDashboard(periodId?: PeriodId): Promise<DashboardData>;
}
```

Для **внешних корпоративных систем** (ABC T2, 1С) — отдельный контракт:

```ts
interface ExternalSystemAdapter {
  readonly kind: ExternalSystemKind; // 'abc-t2' | 'onec' | 'google-sheets'
  readonly displayName: string;
  isAvailable(): Promise<boolean>;
  describeUnavailableReason(): Promise<string | null>;
}
```

Он описывает **возможности**, а не поля: схема ABC T2 и 1С ещё не согласована, и
контракт не должен додумывать её заранее.

### Разделение чтения и нормализации

`GoogleSheetsAdapter` отвечает **только за транспорт**: строит URL, выполняет запрос,
разбирает CSV в `RawRow[]`. Он не знает, что такое «план» или «бонус».

`normalizeDashboardRows` отвечает **только за интерпретацию**: превращает строки листа
«Отчёт» в `DashboardData`. Он не знает, откуда пришли строки.

Благодаря этому транспорт можно заменить на Sheets API, 1С или ABC T2, не меняя ни
строки нормализатора, ни интерфейса.

## Поток данных

```
Google Sheets ──gviz──► GoogleSheetsAdapter ──► normalizeDashboardRows
                                                        │
                                                        ▼
                                              DashboardData (core)
                                                        │
                                                        ▼
                                   DataSyncService (кеш + ретраи + статус)
                                          ↓                    ↓
                              /api/dashboard          /api/sync/status
                                          ↓                    ↑
                                  React + SyncStatusWidget ┘
```

Страница владеет тремя состояниями: выбранный период, статус загрузки и локальный
набор уведомлений/тестов. Глобального хранилища нет.

## Слои API

| Модуль                  | Ответственность                                    |
| ----------------------- | -------------------------------------------------- |
| `modules/dashboard`     | Данные главной страницы, рейтинг, доход сотрудника |
| `modules/sync`          | Статус синхронизации, ручное обновление            |

| `modules/tests`         | Тесты: чтение, прохождение, кураторские действия   |
| `modules/integrations`  | Состояние внешних систем                           |
| `modules/health`        | Живость сервиса                                    |

### Асинхронные обработчики

**Express 4 не ожидает результат обработчика маршрута.** `throw` внутри `async`
превращается в необработанный rejection, и запрос висит до таймаута клиента. Поэтому
все асинхронные маршруты оборачиваются в `asyncHandler` из
`shared/middleware/errorHandler.ts` — он перенаправляет ошибку в error middleware.

### Границы ответственности и защита

| Endpoint                           | Защита                                                        |
| ---------------------------------- | ------------------------------------------------------------- |
| `GET /api/health`                  | публичный, без персональных данных                            |
| `GET /api/dashboard`               | публичный, демо-профиль; `?period=` — 404 для неизвестного    |
| `GET /api/sync/status`             | публичный, без секретов                                       |
| `POST /api/sync/refresh`           | заголовок `x-sync-token`; без секрета — 404, с неверным — 401 |
| `GET /api/notifications`           | только свои; фильтры валидируются                             |
| `POST /api/notifications/:id/read` | только свои                                                   |
| `GET /api/tests/assigned/mine`     | id продавца — из сессии, не из запроса                        |
| `POST /api/tests` (создание)       | `x-curator-token`; без секрета — 404                          |
| `POST /api/tests/:id/publish`      | `x-curator-token` + валидация теста (422)                     |
| `POST /api/tests/:id/attempts`     | ответ не содержит правильных ответов                          |
| `GET /api/integrations`            | только чтение состояния                                       |

**Клиент не может указать источник.** Сервер решает, что читать; произвольные URL и
идентификаторы таблиц от клиента не принимаются.

## Идентификация продавца

`shared/middleware/sellerContext.ts` определяет действующего продавца **на сервере**
и кладёт его в `req.sellerId`. Корпоративной авторизации пока нет, поэтому в
демо-режиме используется фиксированный профиль. Когда появится SSO, изменится только
этот middleware — обработчики продолжат читать `req.sellerId`.

## Синхронизация

`DataSyncService` (в `packages/core`, без фреймворков):

| Механизм                        | Реализация                                                                  |
| ------------------------------- | --------------------------------------------------------------------------- |
| Начальный импорт                | `main.ts` вызывает `syncWithRetry()`, затем включает таймер                 |
| Периодическое обновление        | `setInterval` с интервалом из конфигурации (по умолчанию 5 мин)             |
| Кеш                             | Снимок последней **успешной** синхронизации; при сбое источника отдаётся он |
| Ретраи                          | До `SYNC_MAX_RETRIES` попыток, задержка `base × 2^(n−1)`, максимум 30 с     |
| Защита от параллельных запусков | Общий промис на время выполнения                                            |
| Статус                          | `idle` / `syncing` / `ok` / `error` / `stale`, плюс `servingStaleData`      |
| Устаревание                     | Снимок старше `SYNC_STALE_AFTER_MS` помечается `stale`                      |
| Завершение                      | `stop()` по SIGINT/SIGTERM в `main.ts`                                      |

Таймеры, часы и логгер инъецируются — поведение тестируется без ожидания реального
времени.

## Design system (`packages/ui`)

- `src/tokens/*.ts` — палитра T2, типографика, тени (T2 elevation / neo / glass), радиусы, отступы, переходы.
- `src/styles/global.css` — CSS-переменные; светлая тема по умолчанию, тёмная доступна.
- `packages/config/tailwind/preset.js` — маппинг токенов в классы Tailwind.

Подробно — `docs/design/DESIGN_SYSTEM.md`.

### Слои поверхностей

| Слой       | Когда применяется                                           |
| ---------- | ----------------------------------------------------------- |
| `default`  | Обычная карточка на светлом фоне                            |
| `glass`    | Поверхность над содержимым: рейтинг, прогноз, статус, шапка |
| `neo`      | Акцентный бент-блок: доход, цель, тесты                     |
| `elevated` | Приподнятая карточка с измеренной тенью T2                  |
| `outlined` | Только рамка — для пустых состояний                         |

**Glass используется умеренно** — примерно треть поверхностей: neo-блоки и обычные
карточки дают необходимый contrast.

## Модульные резолверы

`packages/core` импортируется и бандлером (`apps/web`, `moduleResolution: bundler`), и
Node-ESM приложением (`apps/api`, `moduleResolution: NodeNext`). NodeNext требует
явных `.js`-расширений в относительных импортах, а бандлер такие расширения тоже
понимает.

Поэтому **все** относительные импорты в `packages/core` записаны с `.js`:
`import { X } from './domain/dashboard.js'`. Скрипт `scripts/add-js-extensions.mjs`
приводит новые файлы к этому правилу.

## Ограничения

- **FSD-границы проверяются по алиасам.** ESLint `no-restricted-imports` ловит `@/widgets/...` в `shared` и `@/app/...` в `entities`, но относительные импорты через несколько уровней правилами не покрыты.
- `packages/config` не имеет `src/` — конфиги лежат плоско.
- Кеш снимка не персистентный — при перезапуске сервера первый снимок считывается заново.
- gviz отдаёт **вычисленные значения**, а не формулы: формулы листа недоступны, реализованы только восстановленные из файлов.
- gviz при неверном `gid` молча отдаёт первый лист — gid нужно проверять.
- Уведомления хранятся в памяти процесса — при перезапуске теряются.
- Тесты и попытки — тоже в памяти; постоянного хранилища пока нет.
- ABC T2 и 1С не подключены: схемы не согласованы, доступ не предоставлен.
